## Overall: not ready to freeze
The design can work, but it does **not yet establish bubblewrap-equivalent isolation**. The main blockers are cross-runner connectivity, an underspecified admission boundary, mutable client/transcript paths, and treating Kubernetes lifecycle controls as single-writer and experiment-continuity guarantees.
### 1. Session isolation
1. **Blocks — NetworkPolicy is not equivalent to bubblewrap’s disconnected network namespace.**  
   Bubblewrap provides no network interface beyond loopback and two explicitly mounted Unix sockets. The proposed pod has a cluster interface. Kubernetes network policy has node-traffic exceptions, CNI-dependent service/NAT behavior, and no protection unless the actual dataplane enforces it. The IPv4-only exclusions also leave IPv6 unspecified. Consequently, “no DNS, no API server, only two ports” is not established by these manifests alone.  
   **Smallest fix:** specify and test the actual CNI, IPv4/IPv6 behavior, node and host-service access, service-IP translation, link-local endpoints, and API endpoints. Add host-level enforcement where necessary; disable IPv6 if it is not supported by the isolation policy. Treat this as a freeze prerequisite, not an installation check.
2. **Blocks — Every session can reach every thesis and series runner.**  
   The selectors explicitly allow this. A session can probe other daemons and use every runner’s proxy, unlike its former private Unix sockets. This particularly threatens stage 4 identities and stage 10’s main/no-reading/conditional separation.  
   **Smallest fix:** assign runner-specific identities and restrict both ingress and egress to the owning runner. Keep application authentication as a second boundary. Deny session-to-session traffic, including sessions belonging to the same runner.
3. **Blocks — A nonce is an unspecified bearer capability, not an identity design.**  
   “Maps each nonce to one session and agent” leaves entropy, disclosure, expiry, replay, authorization and restart behavior undefined. A shared endpoint must not let a request select its campaign, agent, store, disclosure mode, workspace or transcript destination. Reusing one nonce for workspace download, strategy submission and transcript upload grants unnecessary authority.  
   **Smallest fix:** use unpredictable, per-session capabilities bound server-side to the exact campaign, agent, role and frozen snapshot. Separate transcript/bootstrap authority from evaluation authority; expire capabilities on completion and revoke them before termination. Never expose nonce indexes, other sessions’ errors or capabilities in logs returned to agents. Protect credentials in transit—use authenticated TLS rather than bearer secrets over plaintext pod networking.
4. **Blocks — The daemon becomes a network-facing confused-deputy boundary.**  
   Network isolation cannot prevent leakage through an allowed daemon. An incorrect workspace route, arbitrary file path, debug response, shared cache or identity parameter can disclose the repo, ledger, future data or another agent’s results. Thesis `fetch URL` is also a deliberate internet gateway; restricting the pod itself does not constrain it.  
   **Smallest fix:** preserve server-fixed identities and disclosure rules for every operation, with no caller-selected filesystem paths. Bind market/prices/evaluation responses to the correct snapshot and information horizon. Apply the frozen public-read, redirect, resolved-address and credential restrictions to `fetch`. Test main, no-reading and conditional sessions against each other, including malformed requests.
5. **Blocks — The admission policy is not specified precisely enough to be the security boundary.**  
   “Rejecting any pod that differs” needs an exhaustive definition. Merely checking the listed fields leaves possible init containers, sidecars, alternate commands, lifecycle hooks, probes, `envFrom`, extra Secret keys, projected volumes, `subPath`, process sharing, runtime classes, device access and security-context variations. Restricted Pod Security does not enforce this session template.  
   **Smallest fix:** validate a closed pod template: exactly the expected container, command, arguments, mounts, environment and security settings; no additional execution paths or resources. Require non-root execution, read-only root, dropped capabilities, default proc masking and no shared/host namespaces. Make policy failure fail closed, verify the binding and version compatibility, and test rejection cases as well as accepted pods.
6. **Blocks — Admission has both an identity gap and an internal contradiction.**  
   It applies only to creation by `launcher`. That does not constrain arbitrary pods created by `deployer`, controller-created pods, or later changes outside its matched operation. Meanwhile, “env only from Secret `claude-token`” conflicts with the required literal proxy, daemon, nonce and CLI-control variables.  
   **Smallest fix:** state which principals are trusted, use exact authenticated service-account identities, and enforce sandbox invariants on all session pods regardless of creator and on relevant updates. Explicitly allow only the named Secret key and exact non-secret variables. Deny alternate workload-controller routes and ephemeral-container access to launcher credentials.
7. **Blocks — The old immutable client is missing from the new specification.**  
   Today `/work/<client>` is a read-only bind mount, and its Python runs with `-I`. A downloaded or generated client in writable `/work` can be overwritten with Write and then executed through the otherwise permitted `Bash(./<client>:*)`. A writable wrapper has the same problem. Workspace bootstrap also introduces path-traversal and symlink risks.  
   **Smallest fix:** preserve an immutable client executable and immutable specification outside writable workspace content, while retaining the frozen invocation semantics. Preserve isolated Python imports. Bootstrap only a fixed filename allowlist, rejecting traversal, links and unexpected files.
8. **Should fix — The filesystem, environment and process comparison is too broad.**  
   Bubblewrap clears the environment and supplies a minimal `/etc`. Kubernetes normally injects resolver/search configuration, hosts information and potentially service-discovery environment variables; the image can contain settings, package metadata or unexpected files. “Its own `/proc`” also needs explicit namespace settings. Standard containers usually share the host’s user namespace, unlike `bwrap --unshare-all`. A read-only root alone does not establish equivalent visibility.  
   **Smallest fix:** set `enableServiceLinks: false`, explicitly construct the environment, inspect the final image and runtime mounts, and inventory `/etc`, `/proc`, `/sys` and `/dev`. Explicitly prohibit host PID/IPC/network and shared process namespaces. Use pod user namespaces where supported, or document and accept the changed kernel boundary. Do not count global kernel information already visible through bubblewrap’s `/proc` as a new regression.
9. **Blocks — The transcript transport is not a trusted measurement channel as specified.**  
   The entrypoint being immutable does not make it independent of the agent: it runs in the same pod and apparently under the same UID. A transcript-upload capability visible there can potentially forge, truncate or replay events. Connection loss can silently lose the tail. Counting turns remotely and then requesting deletion permits additional work while deletion is pending.  
   **Smallest fix:** define ordered, session-bound, acknowledged transcript delivery with durable storage and explicit incomplete status. Do not equate uploader authentication with transcript authenticity. Preserve the trusted-client/tool restriction, enforce the turn limit locally as well, and close daemon authorization synchronously at the limit. Hash the persisted transcript, including an explicit termination/incompleteness record.
10. **Blocks — Deleting a pod is not immediate revocation.**  
    Graceful deletion is asynchronous; an unreachable kubelet may not stop a running process. Parent-runner death also does not imply child-session death, unlike bubblewrap’s `--die-with-parent`. Old sessions could continue making calls while a replacement runner resumes.  
    **Smallest fix:** persist session ownership and terminal state; reject calls after lease expiry, cancellation or completion. On runner restart, reconcile existing sessions before launching replacements. Use pod deadlines and deletion for cleanup, not as the sole authority for ending an experiment.
11. **Should fix — The proxy needs a real network-facing protocol and resource specification.**  
    The old Unix-socket implementation has unbounded handler threads, no request-read timeout and incomplete lifecycle cleanup: `close()` stops accepting but does not explicitly terminate established tunnels. It does not require a complete, valid CONNECT header before admission. Making it reachable over TCP broadens the attack surface.  
    **Smallest fix:** enforce bounded parsing, timeouts, connection/byte limits, per-session authentication and audit logs. Close every session-owned tunnel on revocation. Connect only to validated public addresses resolved for the exact allowed hostname; reject private, node, link-local and other prohibited destinations after resolution.
12. **Note — An Anthropic CONNECT allowlist is not an inference-only policy.**  
    An opaque tunnel cannot restrict API paths, models or account operations, and it provides a channel for sending anything the session learns to Anthropic. The shared account credential is already inside the old sandbox, so this is partly an inherited exposure, not solely a Kubernetes regression.  
    **Smallest fix:** accurately describe this boundary and prevent reuse of tunnels between sessions. If inference-only authority is required, use a credential-holding application gateway that exposes only the necessary API operations.
### 2. Runner egress, RBAC and licensed data
13. **Blocks — Public internet egress does not imply homelab isolation.**  
    A homelab service exposed through a public address, reverse proxy or hairpin NAT is allowed on 80/443. So are public licensed-data endpoints. DNS and redirects can resolve to prohibited addresses; node exceptions and address translation complicate the private-range exclusions. A compromised runner can use its allowed internet access, independently of session policy.  
    **Smallest fix:** inventory public and private routes to homelab and licensed-data services, and test those routes explicitly. Prefer per-workload destination policies or controlled egress gateways. Apply resolved-address and redirect restrictions at application fetch boundaries. Protect batch-data services on their receiving side too; namespace separation is not an access-control rule.
14. **Blocks — `deployer` effectively has access to every Secret and PVC in this namespace.**  
    Permission to create arbitrary pods permits mounting namespace Secrets and volumes without permission to `get` Secrets. Workload creation may also permit running as `launcher`. Thus “this repo never reads them” is a workflow statement, not a security guarantee. The launcher’s namespace-wide pod listing and deletion also allow disruption of recorders and other runners.  
    **Smallest fix:** explicitly classify the desktop/deployer as trusted with all live credentials and data, or constrain its pod templates too. Put sessions in a separate namespace and narrow launcher lifecycle authority through a small broker/controller. Do not grant launcher arbitrary deletion of recorder or unrelated session pods.
15. **Should fix — The advertised RBAC cannot update `agent-image`.**  
    `deployer` has no ConfigMap permission, despite being responsible for updating it. Adding broad ConfigMap rights would also let that principal alter the admitted image unless the trust boundary is explicit.  
    **Smallest fix:** make the digest GitOps-owned, or grant narrowly scoped update rights to that named ConfigMap. Freeze its digest per campaign/version rather than allowing an in-progress campaign to inherit a mutable allowlist.
16. **Should fix — Data exclusion and secret custody need affirmative checks.**  
    Neither Restricted Pod Security nor a namespace name prevents an authorized creator from mounting accessible storage. Runner images contain the repo, and the source of stage 3 evaluation data is not described despite the live namespace excluding batch inputs. SOPS also does not protect plaintext Secrets in the API datastore, on nodes or in backups.  
    **Smallest fix:** document the exact evaluation-data path and verify it exposes only authorized research data through the daemon—not licensed batch mounts. Enforce storage restrictions where needed. Record the human’s credential-migration approval, Secret-at-rest/backup protection, and node trust assumptions before deployment.
### 3. Recorders, persistence and cut-over
17. **Blocks — “StatefulSet, replicas 1” is not a fencing guarantee.**  
    A normal partition generally leaves the StatefulSet unavailable rather than safely replacing it. Force deletion or operator recovery can create duplicate identities. ReadWriteOnce permits multiple pods on one node and is not a single-writer lock; it also does not protect the series Job from overlapping attempts.  
    **Smallest fix:** correct the claim. Require storage/process fencing and a documented no-force-delete recovery procedure until the old writer is proven stopped. Use exclusive writer locks for each directory. Local-volume pinning must remain intact during recovery.
18. **Blocks — Kubernetes retries must not rerun an experiment.**  
    Jobs retry by default; StatefulSets restart containers. A crash after daemon evaluation but before recording completion can repeat work or repeat a real-data arm, contrary to the one-attempt rule. “Resumes as today” does not establish exactly-once attempt accounting.  
    **Smallest fix:** durably claim campaign/session/date before launching, make evaluation requests idempotent, and record interrupted attempts as terminal where required. Configure retries deliberately. Infrastructure replacement must not silently become a fresh scientific attempt.
19. **Should fix — SIGTERM and grace periods require end-to-end verification.**  
    Signal forwarding depends on the image entrypoint and PID 1. Polls may block; pacing waits may not wake; a campaign may include multiple sessions. Runner grace does not automatically cover independently running session pods. Recorder checkpointing and final gap logs must finish before forced termination.  
    **Smallest fix:** use an exec-form, signal-aware entrypoint; bound network operations; make waits interruptible; stop scheduling immediately on shutdown. Persist progress and coordinate child-session termination. Test shutdown at every commit boundary and justify grace from measured worst-case work, not nominal session duration.
20. **Should fix — One backed-up node is an availability bottleneck, not HA.**  
    Every persistent workload is pinned to prodesk5. Priority does not prevent node failure, disk exhaustion, pressure eviction or resource contention. The namespace quota can also prevent session or mirror creation; it does not reserve recorder capacity or cap unbounded consumption.  
    **Smallest fix:** state this availability limit. Define requests, limits, emptyDir bounds, reserved headroom, disk monitoring and recovery objectives. Test quota exhaustion and node restart. A second independent recorder is valuable, but Oracle must not be assumed to cover sources it does not record.
21. **Should fix — Clock correctness must survive host changes and restarts.**  
    NTP enabled is not proof of <1 s offset. Wall-clock jumps can affect timestamps, pacing and gap calculations; venue timestamps may be coarse or network-latency-dependent. Selecting the minimum observation timestamp across unsynchronized hosts can fabricate an earlier observation.  
    **Smallest fix:** retain per-host clock measurements and uncertainty, use monotonic time for elapsed intervals, and mark invalid-clock periods explicitly. Validate each source’s clock method and include clock health in the continuity calculation.
22. **Should fix — The mirror is neither an atomic snapshot nor necessarily an immutable history.**  
    Copying active files and independently backing up ledgers can produce mutually inconsistent generations. `--append-verify` is not a substitute for proving that files never change or truncate, and it may rewrite a destination on verification failure. Overlapping CronJobs can write the same destination; failed runs may leave partial artifacts. At ten-minute intervals the mirror also has a nonzero loss window.  
    **Smallest fix:** use `concurrencyPolicy: Forbid`, stage each generation, validate backups and file hashes, then publish a completion manifest atomically. Specify how mutable files are copied and how conflicting history is quarantined. Readers must consume only complete generations. State backup RPO and test restoration.
23. **Blocks — A successful 24-hour overlap does not prove continuity at handoff.**  
    A recorder can stop making successful, complete polls just before desktop shutdown while its pod remains healthy. Matching overlapping items does not detect pagination omissions, edits or delayed publication. An incomplete mirror is also insufficient evidence that authoritative cluster storage is recoverable.  
    **Smallest fix:** gate desktop shutdown on current per-source successful poll watermarks, pagination/edit checks, valid clocks and reconciled overlap. Record exact handoff times and subsequent polls. Keep desktop operation available for rollback until the authoritative data and recovery path are verified.
24. **Should fix — Deletion comes too early in the rollback story.**  
    The plan deletes desktop operational paths after startup, with no acceptance period or rollback gate. A later discovery of incorrect timestamps, incomplete resumability or broken isolation would leave little safe recovery machinery.  
    **Smallest fix:** disable but retain the old paths until explicit acceptance. Rollback must preserve directories and experiment identities and must not rerun consumed arms or dates.
### 4. Criteria and scientific accounting
25. **Blocks — The C5.3 revision can hide a genuine gap unless aggregation is constrained.**  
    Union-of-hosts is legitimate only when at least one healthy recorder actually covered each required interval. It must not reset “first start,” sum overlapping durations, omit an inconvenient host, choose favorable observation times, or infer coverage merely from process uptime. A period missed by every host remains a gap even if backfill later supplies the items.  
    **Smallest fix:** preregister all contributing hosts and compute a source-level UTC timeline from successful, clock-valid, complete polls. Preserve every host’s original logs, all shared outages and the original first start. Deduplicate item revisions deterministically and report earliest valid live observation, denominator and slack without selecting favorable hosts. Report compliance under the original and revised criteria separately.
26. **Blocks — Appending a revision does not make it prospective.**  
    C5.3 has already been measured. A revised acceptance rule must not retroactively turn previous failures into passes. Any changed source/knownAt rule also explicitly requires a fresh recording segment.  
    **Smallest fix:** date and approve the revision before migration measurements used to validate it; identify exactly what changed and which evidence predates it. Obtain fresh validation where required, while retaining—not erasing—the earlier continuity history and failures.
27. **Blocks — Stage 3 refreezing is honest only if “no campaign” is independently established.**  
    An empty series log is insufficient if a campaign launched, made daemon calls, crashed before logging, or has a queued worker. The frozen rule says a harness change requires fresh campaign IDs.  
    **Smallest fix:** reconcile campaign ledgers, daemon calls, transcripts, running/queued jobs and partial directories. Preserve the original freeze and append an explicit superseding freeze. Allocate fresh IDs and prevent stale jobs from using either freeze accidentally. If any real-data arm began, apply the one-attempt rule rather than relabeling it as never run.
28. **Blocks — The proposed hash does not cover the full new leakage boundary.**  
    Agent code, flags and image digest do not pin runner daemon/proxy behavior, admission rules, network policy, workspace construction or transcript handling. These can change the information available without changing the proposed session identity.  
    **Smallest fix:** freeze a versioned deployment manifest containing the relevant runner and agent image digests, daemon/proxy code and configuration, pod template, disclosure rules and effective isolation policies. Detect drift during campaigns; do not silently accept a changed boundary.
29. **Should fix — Stage 10’s version reset is honest, but its accounting needs operational ownership.**  
    The plan correctly excludes old-version theses and elapsed days from the new C10.5 claim. However, stopping the old runner cannot stop required old-horizon scoring: the two-hour resolution obligations continue. Copying individual SQLite backups does not guarantee a consistent ledger/files snapshot, and new startup can duplicate a consumed UTC date.  
    **Smallest fix:** drain and checkpoint all relevant writers, publish a consistent migration snapshot, and assign an explicit worker to resolve old-version registrations under their frozen rules. Preserve version-specific disclosure and scoring links. Persist date/session claims and document how the handoff date is treated. Keep old registrations and scores out of new-version counts.
30. **Should fix — Define the new 28-day window before freezing.**  
    “Days since October 26 do not count” is correct, but a new freeze must establish an exact UTC window and scheduled obligations. Later downtime cannot move that window or excuse missing sessions. Ten resolutions must come from the new frozen track, including continued operation after the initial window when necessary.  
    **Smallest fix:** record the freeze instant, exact first/last UTC dates, benchmark schedule, due-session rules and post-window resolution duties in the new version’s manifest.
### 5. Simpler designs
31. **Should fix — Separate trusted runners from untrusted sessions before adding more admission machinery.**  
    Mixing recorders, secrets, persistent ledgers and disposable session pods in one namespace creates unnecessary RBAC and policy coupling.  
    **Smallest fix:** retain the live namespace for trusted workloads; place sessions in a dedicated namespace with no persistent data, narrowly scoped launcher authority, a fixed pod template and only owner-specific daemon/proxy access.
32. **Note — Preserve the existing sandbox inside a dedicated worker VM if feasible.**  
    A small, always-on VM with no licensed-data mounts can run the existing bubblewrap harness without weakening the general cluster nodes. This preserves private Unix sockets, immutable client mounts and the established lifecycle boundary, avoiding much of the new TCP identity and transcript protocol.  
    **Smallest fix:** compare that design against the session-pod approach before implementing the latter. Recorders can still move to Kubernetes independently; they do not require simultaneous replacement of the leakage-critical agent sandbox.
