### 1. `include_str` breaks the elaboration boundary

`elabIncludeStr` elaborates its argument against `System.FilePath`, then calls `evalTerm`, which compiles and evaluates the elaborated expression. A string literal starts as a `String`, and coercion synthesis supplies the conversion. A project `Coe String System.FilePath` instance can therefore run while elaborating the exact approved literal and return a different path. Ordinary `instance` declarations already occur in step 5. Lean then reads the selected file and inserts its contents as a string literal. The resulting declaration carries neither the coercion dependency nor `Lean.trustCompiler`. Moving the same include to a deeper source directory also changes the selected file, even with the standard coercion. [BuiltinTerm.lean](/nix/store/rgqa0988jgv90q47adl1lc30iqmfapg0-lean-4.34.0/src/lean/Lean/Elab/BuiltinTerm.lean:431) · [Eval.lean](/nix/store/rgqa0988jgv90q47adl1lc30iqmfapg0-lean-4.34.0/src/lean/Lean/Elab/Eval.lean:17) · [FilePath.lean](/nix/store/rgqa0988jgv90q47adl1lc30iqmfapg0-lean-4.34.0/src/lean/Init/System/FilePath.lean:277)
