# Review: BLOCKED

The rewrite fixes several concrete defects, but missing or mismatched evidence can still be reported as established, and recovery can still lose required outcomes.

This is a static review. I read the changed code and tests in full and traced the recording and recovery paths. I did not edit files, execute tests, or independently rerun the supplied dry run. The controlling text is **`audit/criteria.md:479–481`**, read literally.

I disagree with treating either **a cached class plus ledger-file existence** or **a separate decision marker** as sufficient authority. Neither implements “code computes each class from the ledger” across recovery and subsequent evidence loss.

## 2. Blocking findings

### F1. Evaluation payload mismatches still permit establishment

**Outcome affected: Unresolved → Established; potentially Failed → Pass.**

`audit_run` compares only ordered disclosure **kinds** (`gate/agent/campaigns.py:82–88`). The new reconciliation checks full payloads only for successful `history` replies (`gate/agent/campaigns.py:164–168`).

Consequently, an evaluation’s daemon response can disagree with its ledger result while:

- both sides still contain one `eval`;
- the run disclosure matches `run.json`;
- the transcript hash matches;
- all history payloads match.

`holds` remains true, and `swarm_class` can return established (`gate/agent/campaigns.py:166–190`). That is mismatched agent/ledger evidence under frozen v3.

This requires **contract-aware comparison**, not raw equality: successful daemon evaluation responses deliberately project the ledger result and add `remaining` (`gate/agent/daemon.py:71–75`), whereas the ledger disclosure contains additional identity fields (`kernel/mm/src/main.rs:355–358`).

### F2. Summary generation trusts stale classes instead of revalidating evidence

**Outcome affected: Unresolved → Established or Not established; potentially Failed → Pass.**

For an existing class, `row_class` checks only whether an established campaign’s ledger **file exists** (`gate/agent/campaigns.py:608–614`). It does not rerun evidence reconciliation. A recorded `not established` class receives no missing-ledger check at all.

Concrete cases:

1. Two established campaigns lose their run records, transcripts or history logs after their rows are written. Their ledger files remain. The summary still reports established.
2. Eight established campaigns, one unresolved and one not-established campaign pass the arithmetic. Delete the latter campaign’s ledger: its class remains not established, although v3 now requires unresolved, making the correct verdict failed.

The summary reads cached audits and counts from those same rows (`gate/agent/campaigns.py:648–658`), so it does not expose the discrepancy.

### F3. The evidence test still does not establish v3 record integrity

**Outcome affected: acceptance of a stage-4 pass despite unresolved evidence.**

The test checks stored audit flags, activity counts and trial/history indicators, but never checks:

- run-record/disclosure agreement;
- transcript hashes;
- history payload agreement;
- whether a crashed session had received a disclosure;
- the new per-agent `holds`/`received` evidence.

Those values exist in campaign rows (`gate/agent/campaigns.py:233–234`) but are not retained by the summary (`gate/agent/campaigns.py:650–658`). The criterion test therefore cannot inspect them (`criteria/test_stages3to5.py:39–52`).

The guard fixture positively demonstrates the gap: its supposedly good summary contains **none of those v3 records**, yet is accepted before each mutation (`criteria/test_evidence_guards.py:15–22`).

Additional unchecked contradictions include total evaluations disagreeing with the per-agent sum (`criteria/test_stages3to5.py:52`). Unknown class labels also evade all established-only checks, while `swarm_verdict` can call ten unknown labels a pass (`gate/agent/campaigns.py:193–198`; `criteria/test_stages3to5.py:48`).

Thus the test now checks important **C4.3 summary assertions**, but not the full evidence requirements of **C4.3 and v3**.

### F4. Promotion recovery remains incomplete, and pooling ignores recovered promotions

**Outcome affected: Promoted → Unresolved; observed-promotion counts and the exact pooled bound change.**

Two remaining paths:

- **Before marker persistence:** `holdout_decision` returns before `decision.json` is written (`gate/agent/campaigns.py:213–214`). A kill during that interval—or during the temporary-file write before replacement—leaves surviving ledger results but no marker. Recovery records a generic crash (`gate/campaign.py:93–95`), and `row_class` does not reconstruct the decision from the ledger (`gate/agent/campaigns.py:611–613`).
- **After marker persistence:** a later reporting exception can still produce a generic row without `promoted` (`gate/agent/campaigns.py:224–236,353–356`). `row_class` recovers its promoted class, but pooling considers only JSONL rows containing the literal `promoted` field (`gate/agent/campaigns.py:623–639`). The known promotion disappears from both pooled numerator and denominator.

The all-promoted beta-bound endpoint is fixed (`gate/agent/campaigns.py:626`). The remaining issue is which outcomes enter that calculation.

**Promotion-to-unresolved substitution alone does not change verdict arithmetic:** both count toward the same threshold. It does change the separately required classification and pooled reporting.

### F5. A dead series with a torn result can be summarized without counting every start

**Outcome affected: Failed → Not established; started-campaign and outcome reporting change.**

`campaign.records` discards an unparseable append (`gate/campaign.py:46–57`). Summary generation uses those parsed rows alone and does not reconcile started directories (`gate/agent/campaigns.py:647–650`).

For example:

- eight established rows;
- one unresolved row;
- the tenth campaign started, died, and left a torn append.

Summary sees nine campaigns and one unresolved, returning not established. Counting the interrupted start as unresolved produces two unresolved campaigns and therefore failed.

`campaign.resume` repairs this **if the series is resumed first** (`gate/campaign.py:89–99`). The summary path neither performs that reconciliation nor requires it to have happened. The earlier review’s mid-write limitation remains.

## 3. Healthy paths and arithmetic

I found **no erroneous unresolved classification in the specified intact-record case**:

- A refused history call produces no history disclosure and is excluded on both sides of reconciliation (`gate/agent/campaigns.py:68,168`; `gate/agent/daemon.py:80–89`).
- A rejected evaluation maps to `reject` and still counts as an evaluation (`gate/agent/campaigns.py:64–65,423–434`; `kernel/mm/src/main.rs:491–495`).
- A session killed at its designed wall limit is not a crash, including its nonzero signal exit (`sandbox/session.py:129,147–149`; `gate/agent/campaigns.py:126–129`).
- Documented silent agents are correctly exempted **only after their evidence holds** (`gate/agent/campaigns.py:187–190`).

The supplied v2 dry run supports those normal-path checks; it does not judge v3 or establish the failure paths above.

For valid class lists, the verdict arithmetic is correct. In particular, **eight established, one unresolved and one not established passes** under the two separate frozen limits. Two promoted-plus-unresolved fails (`gate/agent/campaigns.py:193–198`).

## 4. Required reporting

Normal completed campaigns now report the previously missing material. Effective-N diagnostics remain in the per-campaign search report, and holdout results remain in campaign rows (`gate/agent/campaigns.py:231–236`; `gate/gate.py:126–135`). The smoke-test qualification matches v3 (`gate/agent/campaigns.py:39–41`).

### F6. Empty searches still omit required effective-N reporting

**Outcome affected: C4.4 reporting/exit compliance; no verdict-arithmetic change by itself.**

When no trial fills, `search_decision` returns before constructing `effective_n` (`gate/gate.py:80–82,95`). That omits cluster counts, per-N screen/StepM decisions and fragility flags.

V3 permits a not-established campaign, but explicitly retains C4.4’s reporting for **every** campaign (`audit/criteria.md:464,479`). Empty results need explicit empty/not-applicable reporting rather than absent fields.

## Verdict

**BLOCKED — not RUN.**

Blocking findings: **incomplete payload reconciliation (F1), stale class authority (F2), insufficient evidence guards (F3), incomplete promotion recovery/pooling (F4), uncounted torn starts at summary time (F5), and incomplete empty-search reporting (F6).**
