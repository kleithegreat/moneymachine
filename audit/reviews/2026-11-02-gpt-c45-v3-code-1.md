# Review: blocking findings

**The code does not implement frozen C4.5 v3 exactly. Missing or mismatched evidence can reach `established`, and the evidence test can accept a result that should be `failed` or `not established`.**

Reviewed the supplied diff, the changed files in full, and the relevant recording, recovery, daemon, harness and gate paths. This is a static review; I did not edit files or execute tests. The controlling text is `audit/criteria.md:479–481`.

## 1. Missing evidence can be treated as proof of silence

**Outcome affected: Unresolved → Established, potentially Failed → Pass.**

`swarm_class` defines silence as no recorded receipt and zero recorded evaluations, then exempts that agent’s missing run or audit:

- `gate/agent/campaigns.py:174–181`
- The new test explicitly expects `(None, None, 0, False)` to permit `established`: `gate/tests/test_agent_campaigns.py:195–197`.

That contradicts v3’s explicit “a ledger, audit or agent record is missing or mismatched” and “missing evidence means unresolved.”

A concrete accepted state is: three active, audited agents satisfy the trial/history requirements; the fourth has no transcript, no daemon calls and no evaluations. Its audit is `None` (`gate/agent/campaigns.py:77–81`), but the classifier permits `established`. Missing evidence is being used to establish that nothing happened.

**Important distinction:** an actual exception before an agent writes `run.json` normally sets the campaign-wide `crash`, making the campaign unresolved (`gate/agent/campaigns.py:200–203,172–173`). A killed series is also recovered conservatively. Those protections do not make the classifier’s missing-evidence exemption correct.

A genuinely documented agent that received nothing and evaluated nothing can correctly be exempted, crashed or not. An undocumented agent is not equivalent.

## 2. “Audited ledger” does not establish record or payload agreement

**Outcome affected: Unresolved → Established, potentially Failed → Pass.**

The audit compares only ordered **disclosure kinds**, plus permitted tool names:

- `gate/agent/campaigns.py:82–94`.

It does not verify:

- the run record against its ledger disclosure;
- presence of that ledger run disclosure;
- the transcript against the run’s recorded hash;
- history reply payloads against ledger history payloads.

The harness records those materials separately (`gate/agent/harness.py:41–45`), but the swarm classification never reconciles them.

Concrete counterexamples:

1. A ledger snapshot contains every evaluation/history disclosure but lacks an agent’s `run` disclosure. The in-memory run exists, so the campaign can be established. The audit’s SQL excludes `run`.
2. The ledger’s history reply contains only self-history, while the corresponding daemon reply names another agent. Both contain one `history` kind, so the audit matches; the daemon reply supplies the cross-agent success.

The latter also violates C4.3’s requirement that history replies match their ledger rows one to one (`audit/criteria.md:461`).

`cross_agent_history` itself compares directory names such as `A1` with returned agent identities correctly for intact, well-formed records. But it trusts daemon payloads alone and accepts any differing value—including a missing `agent`, because `None != "A1"`—without checking ledger agreement (`gate/agent/campaigns.py:97–103`).

Thus the claim **“code computes each class from the ledger, and missing evidence means unresolved” is false**.

## 3. A successful free check is excluded from “any disclosure”

**Outcome affected: Unresolved → Established, potentially Failed → Pass.**

`received` deliberately excludes `check` disclosures and recognizes only daemon `eval`/`history` commands:

- `gate/agent/campaigns.py:155–161`.

Concrete state: an agent receives a successful free-check reply, makes no evaluation, then crashes with its run record and audit present. If the other agents satisfy establishment, the code treats this agent as silent and returns established.

The frozen crash condition says **“received any disclosure”**, not “received market data” or “received a non-free disclosure” (`audit/criteria.md:479`). A successful check is explicitly a disclosure kind in the code (`gate/agent/campaigns.py:66–67`).

There is also an inconsistency: a rejected free check produces a `reject` disclosure, which `received` does count. Neither free check counts as an evaluation (`gate/agent/campaigns.py:403–414`), correctly; that does not authorize excluding successful check disclosures from the crash rule.

## 4. Promotion precedence is lost on reporting failures and recovery

**Outcome affected: Promoted → Unresolved; separate promotion reporting and the pooled bound change.**

Inside `swarm_class`, promotion correctly wins over everything (`gate/agent/campaigns.py:170–173`). But reaching that function requires subsequent evidence processing to succeed.

Concrete state: `holdout_decision` returns a promotion, then parsing a torn daemon log raises while counting evaluations. The outer handler replaces the entire result with a generic crash row:

- gate decision before evidence processing: `gate/agent/campaigns.py:206–213`;
- strict daemon-log parsing: `gate/agent/campaigns.py:71–74`;
- generic replacement: `gate/agent/campaigns.py:333–340`.

The summary then labels that row unresolved because it has no `class` (`gate/agent/campaigns.py:593`), despite v3’s “Promoted … whatever else happened.”

Similarly, killing the series after the gate decision but before the result append produces a recovery row without a class or promotion details (`gate/campaign.py:93–95`). Neither recovery nor summary consults the surviving ledger to recover the gate outcome.

Promoted and unresolved contribute equally to the failure threshold, so this substitution alone does **not** change the verdict arithmetic. It does change the explicitly required separate counts and can remove an observed promotion from pooling.

## 5. The evidence test does not verify the verdict or establishment

**Outcome affected: Failed / Not established → accepted stage-4 pass.**

`criteria/test_stages3to5.py:39–49` trusts the stored `verdict` and class labels.

Concrete false passes:

- Ten classes are `unresolved`, but the summary says `"verdict": "pass"`. No campaign enters the established-only checks. The test accepts what should be **Failed**.
- Ten classes are `not established`, with stored verdict `"pass"`. Again accepted, although the result must be **Not established**.
- Ten classes are `established`, but the three parallel evidence arrays are empty. `zip` performs zero iterations, so the test accepts without inspecting any campaign.
- For an established campaign, all four audits may be `None`; the test explicitly permits that, even when all four agents evaluated.

It also does not require:

- a filled trial;
- at least two evaluating agents;
- run-record agreement or receipt/crash evidence;
- history payload agreement;
- C4.4’s required report fields.

There are useful daemon-level tests—for example, one successful history payload is compared with its ledger disclosure in `gate/tests/test_agent_daemon.py:80–90`. That does not validate every established campaign’s actual evidence.

The new classifier tests reinforce the missing-evidence exemption rather than detecting it (`gate/tests/test_agent_campaigns.py:195–197`).

## 6. Required reporting is incomplete

**Outcome affected: compliance with C4.4/C4.5’s reporting requirements, even when classification is otherwise correct.**

| Required material | Implementation |
|---|---|
| Denials **by kind**, sandbox overrides included | Only integer denial totals survive the transcript audit. No kind or override breakdown is produced (`sandbox/session.py:172–179`; `gate/agent/campaigns.py:600`). |
| Aborts by kind | No abort report is assembled by the swarm result or summary (`gate/agent/campaigns.py:214–217,596–603`). |
| H400 **and C3.2 v3** comparisons | Summary loads H400 for the swarm, but not C3.2 v3’s distribution (`gate/agent/campaigns.py:610–621`). |
| Per-agent evaluations and history calls | Present for intact campaign/run records (`gate/agent/campaigns.py:208–217,601,617–618`). |
| Stop causes | Raw runs preserve `exit`, but the summary retains only `stopped`. A clean exit and nonzero exit can both appear as `"finished"` (`gate/agent/campaigns.py:128–131,619`; `sandbox/session.py:147–149`). |
| Finalist anomaly statement | `with_finalists` is counted, but the required statement about two or more campaigns being far outside the baselines is absent (`gate/agent/campaigns.py:599`; `audit/criteria.md:480`). |
| Zero-fill evaluations | Not reported. Trial construction discards zero-fill evaluations, and the search report supplies no separate count (`gate/gate.py:50–63,76–96`). Evaluations minus N cannot recover this count because duplicates and rejections also contribute. |

The effective-N cluster results and fragility flags are present for nonempty searches (`gate/gate.py:95,126–135`), but that does not satisfy the missing zero-fill reporting requirement.

### Pooled bound

`swarm_report` pools only JSONL rows containing `promoted`; generic crash/recovery rows are omitted (`gate/agent/campaigns.py:594–603`). The supplied v2 log actually contains that omitted row shape (`swarm-null-2.jsonl:10`).

Consequences:

- a promotion lost through finding 4 is absent from the pooled numerator and denominator;
- unknown outcomes disappear without a reported missing-outcome count;
- the resulting complete-case bound must not be presented as covering every started campaign.

For `0 ≤ hits < n`, the formula is the usual one-sided exact 95% binomial upper bound. For **all campaigns promoted**, however, its second beta parameter is zero, yielding an undefined value rather than the required upper bound of **1** (`gate/agent/campaigns.py:603`).

## Classification and arithmetic checks

For valid, correctly evidenced inputs:

- **Promoted:** correctly dominates inside the classifier, but not across later exceptions/recovery.
- **Unresolved:** recorded crashes after evaluations/history, failed audits, and campaign-wide exceptions are correctly unresolved.
- **Established:** the filled-trial and two-active-agent conditions are implemented (`gate/agent/campaigns.py:182–183`), but the evidence weaknesses above permit false establishment.
- **Silent agent:** a documented truly silent agent is correctly exempted; missing evidence and successful free checks are incorrectly folded into that exemption.
- **Lost daemon log:** evaluations remain counted from the ledger. With surviving evaluation disclosures, the audit compares an empty call list against nonempty ledger rows and correctly becomes unresolved (`gate/agent/campaigns.py:82–87,403–414`). Evaluations are not simply erased.
- **Missing ledger during execution:** SQL failure reaches the generic crash path and becomes unresolved, not established. But summary generation trusts an existing stored class and never rechecks whether the ledger still exists (`gate/agent/campaigns.py:588–623`).
- **Killed/torn series:** malformed lines are ignored; resume records started, unrecorded IDs as crashes without retry (`gate/campaign.py:46–57,77–99`). The default unresolved class is conservative absent a recoverable promotion. Before resume, the missing campaign is simply absent from the summary.
- **Pass / Failed / Not established arithmetic:** correct for valid classes. Two promoted-plus-unresolved means Failed; otherwise ten classes and at most one explicit `not established` means Pass; remaining cases are Not established (`gate/agent/campaigns.py:186–191`). In particular, eight established, one unresolved and one not-established passes under the stated separate limits. The problem is evidence/class validation, not this arithmetic.

## Verdict

**BLOCKED — not RUN.**

Blocking findings are false establishment from missing/mismatched evidence, the literal disclosure-rule mismatch, lost promotion precedence, an evidence test that accepts incorrect verdicts, and incomplete required reporting. The valid-class verdict arithmetic and the unchanged frozen identities do not resolve those blockers.
