## Verdict

Both reports reach the same core conclusion, and it is right: **leave the kernel semantics alone and improve the agent-facing surface (input discoverability, diagnostics, examples, a compact authoring syntax compiling to the same JSON). Measure "optimal" as planted-edge search power at a fixed evaluation budget, with null-market false-discovery rate held unchanged.** GPT's report is the more trustworthy: its checkable citations held up, its claims are hedged, and its recommendations separate surface from semantic changes. Argon's report is richer in detail but has several misattributed numbers, one citation that says the opposite of how it is used, and three recommendations that would change a frozen identity or the hypothesis class on thin evidence (128-node cap, mandatory `pre_check`, coarsened feedback). Neither report diagnoses the likely cause of our 11 wasted evaluations; the repo does (below). No citation I checked was fabricated outright, but several figures are wrong or inflated.

Findings the reports missed, from our own files:

1. **The unknown-input failures are probably a documentation mismatch, not agents guessing names.** `kernel/DSL.md` lists `forum_posts` and `gov_proposals` as inputs, and `mm eval` rejects them with `R_INPUT_UNAVAILABLE` on N2 (`audit/stage4/null-summary-v3.json` records 7 such rejections for v3). `mm check` is data-free by design, so it cannot know. The brief says rejections count against the 100 budget. Both reports assume invented names (Argon's "did you mean funding_rate_8h" example is fictional). A one-line statement in the brief of which inputs this market carries would remove the failure with no code change. I did not read the transcripts to confirm every one of the 11.
2. **"Underuse of the budget" is confounded by the null market.** In v3, agents spent 0 to 17 evaluations (4 of 40 agents spent 0) and stopped with `finished` after 220 to 365 seconds. On a pure null market there is nothing to find, so stopping early may be rational. Neither report's recommendation 8 (lineage-summarized history, coarsened feedback) can be judged without a planted-edge market.
3. **Canonicalization and trial dedup already exist.** `kernel/CANONICAL.md` defines an e-graph equivalence key and "a statistical trial is (equivalence key, parameter values)". Argon rec 5.2 and GPT rec 6 are already true of our system.
4. **A mandatory prediction already exists in practice.** `gate/agent/brief.md` requires `prediction.condition` of every strategy, tests it later, and never shows the agent the result. Argon rec 6 asks for something close to this, but proposes evaluating it and flagging "Mechanism-Contradicted" during eval, which would disclose the hidden test.

## Comparison

Agree: JSON stays the canonical hashed AST; an optional compact syntax compiling to it; input catalog and richer `check` at zero cost; example corpus; "optimal" means search power at fixed budget with null FDR unchanged; separate surface from semantic changes; Bend 2 does not prove learnability; unfamiliar syntax mostly costs implementation fidelity, not algorithm choice; expressivity limits are not currently binding (no agent reported an inexpressible idea).

Conflict:
- **Hold.** GPT: add a named `hold` that canonicalizes to today's undefined-weight semantics (surface only). Argon: replace undefined-means-hold with `hold_when(cond, w)` and `rebalance_band`, and treat post-warmup NaN as a warning or 0. GPT is right. Argon's `hold_when` "holds the previous tick's target weight", which is state our kernel does not have (our hold keeps the *position*, which differs from the prior target after the $10,000 order cap and size truncation), and `rebalance_band` needs the same state. That is a new semantic with a new hypothesis class, plus a change to a documented behaviour the pilot depends on.
- **AST size.** Argon wants 4,096 nodes cut to 128. GPT treats limits as sandbox plus regularizer and asks to measure first. GPT is right: the gate's effective-N and SPA/StepM are computed from the evaluated trials, not from node counts, and Argon gives no evidence that any agent used more than a few dozen nodes.
- **JSON authoring.** Argon calls reasoning-first key ordering a 100% trap. The evidence it cites is mis-stated, and our agents write files with a tool after reasoning freely, so the "answer-key-before-reasoning" failure does not apply. GPT's "benchmark your own model" is correct.
- **Feedback coarsening (Thresholdout).** Argon only. It changes what the harness discloses, which is inside the frozen harness hash, and it is a gate/disclosure question, not a DSL question.

Argon adds the typed-holes and dry-run idea (a synthetic 200-tick check), which is reasonable; GPT adds the measurement-model table and the macro-expansion baseline test for "is this feature really sugar", which is the more useful method contribution.

## "Optimal for agents": a proposed definition and experiment (post-pilot)

**Definition.** A surface or tooling variant V of the DSL is better than the baseline B iff, at fixed model, brief wording, evaluation budget (100), market set and gate, V (a) raises **planted-edge recovery** `P(recovery)`: the fraction of agent-campaigns on a planted-edge market in which the agent's selected set contains a strategy whose weight vector correlates at least 0.6 with the oracle weights (`gate/strategies/oracle.json`) *and* passes the search gate; and (b) leaves null false-discovery behaviour unchanged, measured as promotions per null campaign under the same gate (prior: 0 of 10 at v3; pooled bound 0.133). Intermediate metrics, reported but never headline: wasted evaluations (rejections / budget, baseline about 11/208 = 5.3%), checks per first valid candidate, tokens and seconds to first valid candidate, distinct equivalence keys per campaign, evaluations spent, and fraction of agents spending 0.

**Design.** Same kernel, same hashed JSON AST: every variant's output is normalized to the identical canonical JSON before `mm eval`, so the ledger, equivalence key and gate are byte-identical and cannot raise false discoveries by construction for surface variants. Arms: B (current), V1 (input catalog + brief fix + error hints), V2 (V1 + compact syntax). A semantic variant (named `hold`, if it is more than a rename) is added only as a macro-expansion check: if V's strategies expand to the same AST set as B's, it is sugar. Fresh campaign ids; null FDR is re-checked on N2 with the new arm at the same size as C4.5.

**Size (GPT's figures reproduce: 80% vs 90% needs about 199 per arm at 5%/80%).** The binding cost is agent campaigns, not statistics. v3's ten null campaigns of four agents took the account's usage windows, paced by `gate/compute`/usage. Plan: (1) a **zero-cost microbenchmark** first: 200 to 300 fixed intents, no market data, scored on first-valid rate and wasted-input rate (cheap, large n); (2) a **planted-edge screen**: 3 arms x 12 campaigns x 4 agents = 144 agent runs, enough to see a 25-point lift in `P(recovery)` only if the baseline is near 30% (about 93 per arm needed for 30% to 50%, so this screen is underpowered for anything smaller, and decisions at that size are directional); (3) a **confirmatory** run of the best arm vs B of 25 to 30 paired campaigns, plus 10 null campaigns for the new arm (rule of three: zero promotions in 10 does not rule out a rate above about 0.26, which is why it is a non-regression check, not proof). Precondition: planted-edge markets with agents must exist; stage 2 has the calibrated planted markets for the searcher, but a mean small enough to be recoverable by an LLM agent at all is unknown, so run one pilot campaign to see whether the baseline `P(recovery)` is neither near 0 nor near 1. If it is near 0, change the planted strength, not the DSL.

**Why this cannot raise false discoveries.** Surface variants change only how a strategy is written; the kernel sees identical canonical ASTs; every `check` and `eval` is counted in the same ledger; the gate and holdout are untouched; null campaigns use fresh ids; none of it reads the holdout or the forward window [2026-11-01, 2027-01-31). The one real risk is **search-induced**: an interface that makes agents run more evaluations raises the multiple-testing penalty. The null re-check measures exactly that, and the Argon point that `P(recovery)` can fall as N grows is worth keeping as a reported (not decisive) secondary outcome.

**Caveats the reports underplay.** (i) Budget use on nulls is not informative about search quality. (ii) The agent model is frozen to one Claude snapshot; format effects are model-dependent (the "Format Tax" and causal studies both find little effect on strong closed models). (iii) Any change to `kernel/DSL.md`, `gate/agent/brief.md`, or the harness forks frozen identities (`harness_hash`): fresh null campaign ids and a later holdout are needed for any real arm. (iv) "No agent reported an inexpressible idea" is weak evidence of sufficiency, as GPT says: use a fixed mechanism-task bank scored blind.
